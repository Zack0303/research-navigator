# Output templates

Use these shapes so outputs are short, comparable and easy to share with a supervisor. Fill only what is known; write `unknown` or `to decide` rather than guessing. Translate headings into the guidance language; keep proposal text in the submission language.

---

## T1 One-page research brief (planning)

The main planning output. Aim for one page. It is meant to be shown to a supervisor **early**.

```
Working title:
Anchor  — for whom / what they need answered / why it matters to them:
Research question (one sentence; plus at most 2 sub-questions):
Why now — the problem or gap, with its evidence status (searched / not yet searched):
Nearest neighbours (3–5) and what this adds:
Approach — data or material, method, and why this method fits the question:
How we will know — evaluation, comparison or interpretation criteria:
Smallest feasible version  |  optional extensions:
Pilot step and what it will measure:
Risks and fallbacks (access, ethics, time):
Known requirements  |  unknown requirements (see table):
Decisions needed from the supervisor (max 3):
```

Requirements table (always in planning; never hide uncertainty in prose):

| Requirement | Value | Source / locator | Status |
|---|---|---|---|
| Word limit | | | verified / supplied / unknown |
| Format and sections | | | |
| Deadline | | | |
| AI-use and translation policy | | | |

## T2 Review report (feedback on a draft)

```
Scope: what was reviewed (version, sections), guidance and submission languages.
Verdict in one sentence: the single most important thing to fix.
Strengths (2–3, specific).
Priority issues (max 5, most important first):
  #  | issue | where in the draft (quote ≤ 1 short line) | why it matters | concrete revision
Claim-strength table (C3) for the key claims.
Requirements: rule | applies? | source | met / partial / missing / unknown
Unknowns and questions for the student.
Next three actions.
```

Separate two lenses: programme requirements (only from inspected sources) and academic coherence (your advice). Never present advice as a rule.

## T3 Paragraph brief (before writing a section)

Write the logic before the prose. The student (or, where policy allows, a drafting assistant) writes from the brief; then check the draft against it.

```
Section purpose — the one sentence this section must show:
Paragraph | claim | evidence (source + page, or own data + table) | must NOT say
1         |       |                                                |
2         |       |                                                |
Check after writing: every number matches the data; every citation supports its sentence; no claim is stronger than the brief.
```

## T4 Literature-review setup sheet

See lit-review.md for the reasoning.

```
Review question:
Review type and why (scoping / systematic / narrative / rapid):
Anchor (C1) and nearest existing reviews (C2):
Sources (databases, other routes) and date range:
Search strings — draft, not yet run:
Pilot: run counts; screen 50 records; time taken; estimated total effort:
Inclusion / exclusion criteria (each testable from a title/abstract or full text):
Who screens; how disagreements are resolved; share double-screened:
Data extraction: descriptive fields (with not-reported / unclear codes) | claims to appraise in depth and the rule for choosing them:
Search log fields: date, database, exact string, filters, count, export file:
```

## T5 Where-we-are note (resuming work)

Keep it to half a page. Replace it each session; do not append forever.

```
Date:
Anchor (unchanged? if changed, why and who agreed):
Current master copy and last version shared (with whom, when):
Done since last note:
Decided (by whom):
Open questions:
Next one action:
```
